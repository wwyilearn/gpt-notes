【学习笔记】：
RAG:Retrieval-Augmented Generation
Retrieval：检索，先从资料库里找相关内容
Augmented：增强，把找到的内容补充给大模型
Generation：生成，让大模型基于这些内容生成答案

agent:能自己根据目标，决定调用哪些工具，分几步完成任务
多步骤
工具调用
规划
执行
检查
循环

RAG：让大模型会查资料
Agent：让大模型会分步骤做任务
RAG + Agent：让大模型一边查资料，一边完成复杂任务

Chunking：把长文档切成小文本块
大模型不能每次都把整篇文章塞进去，而且检索也需要颗粒度
Chunking 会严重影响 RAG 效果。切太小，信息不完整；切太大，检索不精准

Embedding：把文本转换成一串数字向量，用来表示它的语义
RAG 依赖 embedding 做语义检索

向量检索：根据语义相似度，在文档库里找到和问题最相关的文本块。
1. 文档 chunk 被 embedding 成向量
2. 用户问题也被 embedding 成向量
3. 系统比较“问题向量”和“所有文档块向量”的距离
4. 找出最相近的几个 chunk
常见向量数据库/向量索引：它专门存储和检索 embedding 向量

Reranker：
重排序器
它的作用是：对初步检索出来的结果重新排序，把真正相关的内容排到前面。

Citation grounding 回答中的结论必须能追溯到文档来源：减少幻觉 方便验证 让回答更可信 更像真正的学术助手

Eval 是 evaluation 的简称 评估系统效果

RAG 项目常见评估维度：
Retrieval accuracy：检索到的文档片段是否相关
Answer faithfulness：回答是否忠实于资料
Answer relevance：回答是否回答了问题
Citation accuracy：引用是否真的支持答案
Hallucination rate：幻觉率
Refusal accuracy：资料不足时是否能拒答

Ollama：本地大模型运行器

Prompt Engineering：设计输入给大模型的指令，让它更稳定、更准确地完成任务。
